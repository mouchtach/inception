01 — Services

Every container, its purpose.

01
NGINX
The sole public entry point. Handles TLS termination with a self-signed certificate and proxies all traffic — WordPress via FastCGI, Adminer via HTTP proxy. Nothing reaches the stack without going through here.
:443
02
WordPress + PHP-FPM
The main application. Installed and configured automatically via WP-CLI at startup. Creates an admin user and a regular user, connects to MariaDB, and enables the Redis object cache plugin.
:9000 (internal)
03
MariaDB
The relational database layer. Initialised by a shell script that creates the database, user, and sets root password — all sourced from Docker Secrets. Data persists in a named volume.
:3306 (internal)
04
Redis
In-memory object cache wired to WordPress. Reduces redundant database queries and speeds up page generation. Password-protected via Docker Secrets and configured through a custom redis.conf.
:6379 · bonus
05
FTP Server (vsftpd)
Provides FTP access to the WordPress volume. Useful for direct file management and uploads. Operates in passive mode with a defined port range (30000–30009) and dedicated FTP user credentials.
:21 · bonus
06
Adminer
Lightweight single-file PHP database manager served via NGINX proxy. Provides a clean web UI for browsing and managing the MariaDB database without needing a CLI.
:8080 (proxied) · bonus
07
Portainer
A full Docker management dashboard. Mounts the Docker socket directly to give real-time visibility into all containers, volumes, networks, and images running in the stack.
:9443 · bonus
08
Static Website ← you are here
This page. A self-contained Nginx container serving a static HTML overview of the entire Inception infrastructure. No PHP, no database — pure HTML/CSS served on port 5000.
:5000 · bonus

03 — About

Infrastructure from scratch.

Inception is a 42 school project that requires building a complete web infrastructure using Docker Compose — no pre-built images from Docker Hub, no shortcuts. Every service is compiled from a custom Dockerfile based on Alpine Linux.

The constraint forces a deep understanding of how each service actually works: how NGINX speaks FastCGI, how WordPress bootstraps itself, how MariaDB initialises its grant tables, and how secrets flow securely into containers without touching environment variables.

All services share a single bridge network named inception, communicate by container name, and only expose the minimum ports required to the host. Sensitive credentials are handled exclusively via Docker Secrets. 

# docker-compose.yml — excerpt

services:
  nginx:
    build: ./requirements/nginx
    ports: [ "443:443" ]
    networks: [ inception ]

  wordpress:
    build: ./requirements/wordpress
    expose: [ "9000" ]
    secrets: [ db_password, wp_password ]

  static:
    build: ./requirements/bonus/static
    ports: [ "5000:5000" ]
    networks: [ inception ]
    restart: unless-stopped

networks:
  inception:
    driver: bridge
